# M4b manual checks

M4b's smoke drives the four tabs, Placement, Presets, Background, Details, Text and the window's keys through the test input bridge (`brg m4b`, plan item 15). The bridge has three limits that matter here, and each one leaves a check with a person:

- It raises key downs and KeyBindings, never text input. The tool letters and the character keys (`[ ] { } + - r`) are text input (K2), so the bridge cannot type them.
- The window reads Shift from the physical keyboard, which the bridge never sets, so Shift+arrow and Shift+bracket reach the router without Shift.
- A WPF slider thumb drag reads the system's mouse button state, so the bridge cannot drag a slider. It sets slider values through UI Automation instead, which skips the drag gesture.

The router and view-model unit tests cover each of these. The items below check them end to end on real hardware, plus what no automation can judge: an Explorer drag, a non-US keyboard, a display above 100%, and the look itself.

Run the Release build, `dotnet run --project src/RBX15.App/RBX15.App.csproj -c Release --no-build`, at 100% unless the item says otherwise. Answer each item pass, fail or not run. MAN-1 to MAN-3 are in [m4a-manual.md](m4a-manual.md).
